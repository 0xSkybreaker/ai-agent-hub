# 记忆与上下文管理

## 记忆层次

```
┌─────────────────────────────────────────┐
│              长期记忆                     │
│  (向量库 / 知识图谱 / 文件系统)            │
│  持久化的知识、用户偏好、历史经验           │
├─────────────────────────────────────────┤
│              工作记忆                     │
│  (对话窗口 / 上下文)                       │
│  当前任务的中间步骤、临时状态               │
├─────────────────────────────────────────┤
│              感知记忆                     │
│  (当前消息 / 最新观察)                     │
│  本轮交互的即时输入                        │
└─────────────────────────────────────────┘
```

## 短期记忆 (Short-term Memory)

### 对话窗口管理

- **滑动窗口**：保留最近 N 轮对话，丢弃旧的
- **摘要压缩**：对历史对话做摘要后保留摘要
- **重要信息提取**：提取并保留关键事实、决策、状态变更

### Token 预算分配

```
总计 128K tokens → 如何分配？
├── 系统提示词：2K
├── 工具定义：3K
├── 工具结果：40K（预留）
├── 长期记忆注入：5K
├── 对话历史：50K
├── 输出预留：8K
└── buffer：20K
```

## 长期记忆 (Long-term Memory)

### 实现方式

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 向量数据库 | 嵌入 + 相似度检索 | 语义匹配好 | 精确匹配弱 |
| 知识图谱 | 实体-关系-实体 | 逻辑推理强 | 构建成本高 |
| 全文检索 | 关键词匹配 | 精确查找 | 语义理解弱 |
| 混合检索 | 向量 + 关键词 | 互补优势 | 实现复杂 |

### 记忆更新策略

- **增量写入**：每次对话结束写入新的记忆片段
- **合并更新**：相似的记忆自动合并去重
- **衰减机制**：长期未使用的记忆权重降低
- **反思提炼**：定期从原始记忆提炼高层次的总结

### Mem0 类方案

```python
# 概念示例
memory.add("用户偏好 Python，不喜欢 Java", user_id="user_123")
memory.add("上次讨论了 RAG 的实现方案", user_id="user_123")

# 检索时自动做语义匹配
results = memory.search("用户偏好什么语言", user_id="user_123")
# → "用户偏好 Python，不喜欢 Java"
```

## RAG 在 Agent 中的应用

```
用户提问 → 检索相关记忆/文档 → 注入上下文 → LLM 生成回答
                ↑
        长期记忆 / 知识库
```

### RAG 的层级

1. **基础 RAG**：单次检索 + 注入
2. **Agentic RAG**：Agent 自主决定何时检索、检索什么
3. **Multi-hop RAG**：多次检索，后一次检索依赖前一次结果
4. **Corrective RAG**：检索后自查质量，不够好就重新检索
