# AI Agent 面试备战攻略

## 总体策略

Agent 面试和普通后端/算法面试最大的区别：**面试官不在乎你背了多少概念，他们想看你是不是真的动手做过。**

核心原则：**以项目驱动学习，以输出倒逼输入。**

## 阶段二：动手做 2-3 个项目（3-4 周）

**这是决定面试成败的关键。** 看 100 篇博客不如写一个能跑的 Agent。

### 项目 1：最小可行 Agent（必做，帮助理解核心）

**目标**：用最少的依赖实现一个 ReAct Agent

- 直接用 `openai` / `anthropic` SDK，**不要用 LangChain 等框架**
- 实现工具注册、ReAct 循环、终端输出
- 挂 3-5 个工具：搜索、计算器、读文件、查天气 API、一个数据库查询

**你会真正理解**：
- Agent 循环的每一步发生了什么
- 工具定义怎么写 LLM 才不容易出错
- 错误处理和重试的重要性

**预期耗时**：2-3 天（业余时间）

### 项目 2：垂直场景 Agent（选一个方向深挖）

选一个你感兴趣的方向做一个完整的 Agent：

| 方向 | 项目 | 涉及的面试点 |
|------|------|-------------|
| 客服 | 退换货 Agent | 多轮对话、槽位填充、HITL、异常处理 |
| 知识库 | RAG 问答 Agent | 检索、Memory、引用溯源、chunk 策略 |
| 代码 | 代码审查 Agent | 工具调用、结构化输出、并行执行 |
| 自动化 | SQL 查询 Agent | Text-to-SQL、安全（防注入）、结果解释 |
| 研究 | 多源调研 Agent | 多工具编排、长任务、摘要压缩 |

**你会真正理解**：
- 一个完整 Agent 系统的边界在哪里
- 哪些场景 Agent 能做，哪些做不了
- 怎么评估和优化

**预期耗时**：1-2 周

### 项目 3（加分项）：多 Agent 协作

在项目 2 的基础上拆成多个 Agent 协作，体验：
- 消息协议设计
- 任务分配和冲突解决
- 多 Agent 调试的地狱难度

## 阶段三：源码级理解（1 周）

不要每个框架都看，**挑一两个精读**：

### 推荐精读

- **LangGraph 源码**：重点看 `StateGraph`、`ToolNode`、checkpoint 机制
  - 理解状态机在 Agent 中的应用
  - 理解中断和恢复如何实现
- **或 Anthropic/OpenAI 官方 Agent 示例**：看官方推荐的最佳实践

### 不需要精读

- LangChain 的全部源码（太庞大，投入产出比低）
- CrewAI / AutoGen 的实现（面试基本不考）

## 阶段四：面试专项训练（1-2 周）

### 准备 3 个故事

面试官一定会问"讲讲你做过的最复杂的 Agent 项目"。你需要准备好：

1. **技术最复杂的** — 讲架构决策和技术难点
2. **踩坑最多的** — 讲你遇到什么问题、怎么解决的（这比成功故事更有说服力）
3. **效果最好的** — 用数据说话（准确率提升了多少、延迟降低了多少）

每个故事按 **STAR 框架** 组织：
- **Situation**：背景和要解决的问题
- **Task**：你的任务是什么
- **Action**：你具体做了什么（重点：为什么这么做，而不是那么做）
- **Result**：结果和反思

### 准备好高频题目的回答

面试前，确保你能**流利地用口语**回答以下问题：

1. Agent 和传统 chatbot 的本质区别是什么？
2. 你设计的 Agent 架构是什么样的？为什么这么设计？
3. 工具调用失败你怎么处理？（这是所有面试官的"安全检查"问题）
4. 选 LangChain 还是原生 API？为什么？
5. 怎么控制 Agent 的成本？
6. 你的 Agent 出了 bug，怎么排查？
7. 如果让你重新设计你的项目，你会改什么？

### 白板编程准备

一定会有一道代码题，方向通常是：
- 实现一个简单的 Agent loop（见 08-coding.md）
- 实现工具注册/调度器
- 实现一个简单的 Memory 模块
- 或者直接让你 review 一段 Agent 代码，找问题

**练习要点**：
- 先讲思路再写代码
- 写的过程中不断说话解释
- 主动提边界条件和异常处理
- 写完主动说"这里可以优化"

## 阶段五：简历和作品集

### 简历上怎么描述 Agent 项目

❌ 差的写法：
> 使用 LangChain 搭建了一个智能问答系统

✅ 好的写法：
> 基于 ReAct 范式实现了一个带记忆和工具调用的 Agent 系统，支持 20+ 工具并行调度。设计了分层记忆架构（短期摘要 + 长期向量检索），通过混合检索和 rerank 将 RAG 准确率从 72% 提升到 89%。集成 LangFuse 实现全链路追踪，P99 延迟控制在 3s 以内。

## 最后几个关键提醒

1. **不要沉迷框架**：面试官更在意你理解底层原理。会说"我用 LangChain 搭了个 Agent"的人很多，会说"我选择在每一步做 A 而不是 B 因为 C"的人很少。

2. **实际动手 > 看文章**：Agent 方向 90% 的"理解"来自于你亲手调过一个不听话的 Agent、亲眼看到它循环输出同样的话 20 次之后的顿悟。

3. **准备失败案例**：面试官一定会问"你的 Agent 失败过吗？怎么处理的？"——这是在考察你是否真的在生产环境用过 Agent。如果你没有失败案例，说明你做得不够深。

4. **保持跟进**：Agent 领域变化极快。面试前一周，至少看一眼最近一个月 Anthropic/OpenAI/Google 发布了什么新东西。面试官可能会问"你对最近 XXX 发布怎么看"来判断你是否真的关注这个领域。

5. **Show, don't tell**：如果面试允许屏幕共享，直接打开你的项目 demo 比任何话都有说服力。
