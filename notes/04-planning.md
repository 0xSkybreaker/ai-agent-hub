# 规划与推理

## 任务分解 (Task Decomposition)

### Chain-of-Thought (CoT)

让模型逐步推理，不直接给答案：

```
问题：一个班有 30 个学生，男生比女生多 4 个，问男生有多少个？

CoT:
- 设女生有 x 个，则男生有 x+4 个
- x + (x+4) = 30
- 2x = 26
- x = 13
- 男生有 13 + 4 = 17 个
```

### 分解策略

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| 线性分解 | 步骤 1→2→3，明确依赖 | 流程化任务 |
| 并行分解 | 识别独立子任务同时执行 | 多维度分析 |
| 层次分解 | 先分子目标，子目标再分子步骤 | 复杂项目 |
| 动态分解 | 执行中根据反馈调整后续计划 | 不确定性高 |

### 常见技术

- **Few-shot 示例**：在 prompt 中给分解示例
- **Plan template**：预定义常见任务的分解模板
- **LLM as planner**：让 LLM 自己生成计划

## 推理增强技术

### Tree-of-Thoughts

```
            [问题]
           /   |   \
        [A方案] [B方案] [C方案]    ← 广度探索
        /  \    /  \    /  \
       ... ...  ... ...  ... ...   ← 深度推理
              ↓
        [选最优路径] + [回溯剪枝]
```

### Graph-of-Thoughts

比 Tree 更灵活，子节点可以合并、交叉引用：

- 允许多个不同思路融合
- 支持循环验证
- 更适合开放性推理任务

### Self-Consistency

同一个问题跑 N 次采样，投票选最一致的答案：

- 提高推理准确率 5-15%
- 成本是原来的 N 倍

## Self-Reflection / Self-Correction

### 机制

```
执行 → 自我评估 → 发现问题 → 修正 → 继续执行
```

### 反思内容

- 当前步骤是否正确？
- 有更快/更好的方法吗？
- 是否需要回退或重新规划？
- 是否遗漏了什么？

### 实现方式

- **显式反思提示**：在每一步之后加"请评估你刚才的回答是否正确"
- **外部验证**：工具返回结果后做一次合理性检查
- **反思记忆**：把反思结果写入记忆，后续任务可参考

## 防止 Task Drift

### 漂移原因

- 上下文太长，忘记最初目标
- 中间步骤产生的新信息误导方向
- LLM 倾向"继续做"而不是"检查目标"

### 防止方法

- **目标锚定**：每 N 步重新在一开始写下当前目标和初始目标的对比
- **中间检查点**：关键节点验证是否还在正确轨道上
- **进度追踪**：维护一个已完成/未完成子任务的追踪列表
- **早停机制**：检测到偏离时主动中止或重定向

## 面试常见追问

2. Tree-of-Thoughts 的计算成本怎么控制？
3. 如果一个 Agent 的规划很差，你会从哪些方向改进？
4. Self-reflection 会不会让 Agent 陷入过度自我怀疑而无法推进？
5. 如何判断一个任务是否需要分解？什么任务不需要？
